# Deploying Sconeos on Vercel (`sconeos.gattey.com`)

## Connect the GitHub repo

1. Push this repository (`dgattey/scone-os`) to GitHub.
2. In Vercel (`dylan-gattey` scope): **Add New Project** → import `dgattey/scone-os` as `scone-os`.
3. Set **Root Directory** to `server` (required; the Next.js download site lives there).
4. Framework preset detects **Next.js** automatically.
5. Add custom domain **`sconeos.gattey.com`** (and redirect `scone-os.vercel.app` → `sconeos.gattey.com`).

Vercel only deploys `server/` when root directory is set.

macOS Sparkle files (`appcast.xml` and `Sconeos-<version>.zip`) in `server/public/` are committed by `.github/workflows/release-macos.yml` when the app changes on `main`. Vercel’s normal Git Production deploy serves them at `https://sconeos.gattey.com/appcast.xml` and `https://sconeos.gattey.com/download/macos`.

## How auto-updates & signing work

- Small household install: **ad-hoc** code signing (`-`) + `com.apple.security.cs.disable-library-validation` (`Sconeos.local.entitlements`) + Sparkle 2 EdDSA. No Apple Developer Program required.
- Ad-hoc signing (`-`) with `com.apple.security.cs.disable-library-validation` works cleanly with macOS Gatekeeper's **Privacy & Security → Open Anyway** flow (whereas untrusted self-signed X.509 certificates get killed by `syspolicyd`/`amfid` on macOS Sequoia/Tahoe when quarantined).
- Sparkle 2 validates and installs updates via the EdDSA signature (`SUPublicEDKey` in `Info.plist` + `sparkle:edSignature` in `appcast.xml`, generated by `scripts/generate-sparkle-key.sh`).
- The macOS app checks `https://sconeos.gattey.com/appcast.xml` (Sparkle 2, EdDSA signed).
- Push/merge to **`main`** with macOS app changes → `.github/workflows/release-macos.yml` reads the merged PR's `# Release info` checkbox (`Major` / `Minor` / `Patch`), builds & ad-hoc signs `Sconeos.app`, updates `server/public/appcast.xml` and `server/public/Sconeos-<version>.zip`, commits `server/public/` + `VERSION`, pushes to `main`, and creates a GitHub Release.
- Sparkle only renders the winning appcast item's `<description>`, so `scripts/cumulative-release-notes.sh` bakes the new version's notes plus the previous 9 versions (from the prior `appcast.xml` and GitHub Releases) into it. Preview the output with `./scripts/test-cumulative-release-notes.sh`.
- That release commit only touches `server/public/**` and `VERSION`, so the workflow does **not** run again (no loop). Vercel’s Git integration deploys the updated `server/public/` automatically.

## Releasing from a Mac without CI

From a clean `main` that matches `origin/main`:

```bash
./scripts/release-local.sh --dry-run   # print the version and notes
./scripts/release-local.sh             # build, sign, commit, tag, push
```

It batches every PR merged since the last `Release v…` commit and bumps by the highest checked `# Release info` box among them (pass `major`, `minor`, or `patch` to override). It needs the Sparkle key at `.cert/sparkle_ed.key` (or `SPARKLE_ED_KEY_FILE`). The pushed `server/public/` deploys through Vercel like a CI release.

## GitHub Actions secrets

Push the Sparkle EdDSA signing secret:

```bash
./scripts/export-ci-secrets.sh
```

| Secret | Purpose |
|--------|---------|
| `SPARKLE_ED_PRIVATE_KEY_BASE64` | Sparkle EdDSA private key for signing release archives in `appcast.xml` |
